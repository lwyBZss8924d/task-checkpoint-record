# Security policy

This project handles private local trajectory metadata. Report a suspected issue
without attaching account credentials, native histories, private databases or
unredacted model requests. Prefer a minimal synthetic reproduction, affected
version, expected boundary and exact public file/symbol.

Use the repository's private vulnerability-reporting channel if enabled. Otherwise,
open an issue requesting a private contact method and include no exploit data or
private material. The project does not promise a vulnerability response SLA.

Review explicit source roots, dedicated service authentication, hook-plan changes
and runtime starts. A checkpoint URI, task binding or plugin installation grants no
remote upload permission. Default retrieval returns metadata; source following and
external scoring require their explicit contracts. Keep profile/state volumes out
of releases, build contexts and CI artifacts.

The pre-1.0 release is evolving. Report the tested commit, package version, Codex
version and operating-system/container platform. CI source tests, compatibility
probes and authenticated runtime observations carry separate acceptance scopes.
